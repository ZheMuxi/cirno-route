# Pi 自动路由

开启 `/bakarouter` 后，每轮普通用户输入先由本地 Gemma 4 E4B 评估任务能力，再由本地价格策略选择模型，随后由 Pi 使用选中模型回答。`/classify` 始终只显示评分和推荐，不切换模型、不执行任务，即使自动路由已开启也一样。

## 使用

重启 Pi 或执行 `/reload` 加载扩展，然后：

```text
/bakaprice 希望便宜
/bakarouter
用 Python 实现二分查找，补上边界测试。
```

可以把价格档位改为“均衡”或“接受昂贵”。三档能力门槛与同分规则保持不变，详见 [模型价格](model-pricing.md)。普通对话不显示各模型分数，每次回答显示实际 `provider/model`；想查看完整评分时使用 `/classify 任务`。

| 操作 | 结果 |
| --- | --- |
| `/bakarouter` | 开启普通输入自动选模，之后每轮重新评估任务 |
| `/bakarouter off` | 停止后续自动选模，保留当前已选中的模型 |
| `/model` | 手动更换当前模型；路由开启时下一轮普通输入仍会重新选模 |
| `/classify 任务` | 只评分和推荐，当前模型保持原样 |
| `/bakaprice …` | 保存价格偏好，后续路由使用新设置；本命令不调用回答模型 |

自动路由默认关闭；重启或 `/reload` 后需再次开启。价格偏好会跨重启保留。自动选模只修改当前会话，不改 Pi 新会话的默认模型。关闭路由不会恢复启动时的模型，需要时使用 `/model` 选择。

## 执行与失败处理

扩展在 Pi 1.2.0 的 `before_agent_start` 中等待分类及模型切换完成，再由 Pi 发出本轮首个请求。通过 `pi.setModel()` 使用注册表中的完整模型对象，不自行拼接 API、重发任务或绕开 Pi 的工具与认证处理。Python 分类器本身仍只评分，CLI/HTTP `/v1/classify` 不增加模型调用。

- 推荐必须来自有效 Gemma 结果、有候选自己的证据且能力至少 3/4；不采用规则回退的 `fallback_candidate_id`。
- 从当前 Pi 注册表精确匹配 provider/model；执行前另检查网关候选是否仍在网关 `/models` 中。资料未知的候选不会凭价格成为执行对象，其他有依据的候选仍可参与。
- 一轮只选一次。同轮工具调用及其后续生成继续使用该模型，避免在工具调用中途切换。自定义扩展消息、重试和运行中追加的 steer 消息不单独触发选模；下一次新的用户轮次再评估。
- 分类失败、没有达标推荐、候选已移除或切换失败时给简短提示，保留当前模型回答。不自动轮番尝试其他模型；执行 API 的余额、限流、网络等错误仍由 Pi 显示和处理。
- 分类期间关闭/重新开启路由、改变价格档位或手动更换模型，会使这次旧选择失效。切换接口等待认证期间失效时，尽可能恢复之前的模型或较新的手动选择；恢复失败会停止该轮，避免用不确定的选择继续执行。
- 附图和过大任务沿用分类器现有的拒绝规则，普通对话提示后使用当前模型。该回退策略不是外发拦截。

实际回答模型仍从 assistant 消息读取，而不是把推荐模型当作已使用模型；其他扩展改变模型时也按实际消息标注。Pi 自己记录会话模型切换；普通输入不保存评分卡，也不把分类结果加入执行模型上下文。

JSON 模式在 stderr 输出 `cirno-routing`（成功切换或沿用相同模型，包含模型标识、价格档位和规则原因），以及开关事件 `cirno-router-status`。这些事件没有任务正文、候选分数或密钥。`cirno-execution-model` 标记实际响应模型，`cirno-classifier-warning` 报告分类/路由失败。

分类仍只读取本轮任务，不能保证理解省略上下文的“继续修改它”等请求。能力资料和跨批分数尚未校准，部分价格为网关参考价；开启自动路由并不证明质量或成本优于手动选模。不包含用户习惯自适应。

## 验证

```bash
node --test packages/pi-extension/*.test.mjs
.venv/bin/pytest -q
.venv/bin/ruff check .
.venv/bin/ruff format --check .
# 实际调用本地 Gemma 和候选回答模型：
.venv/bin/python scripts/pi-routing-smoke.py
.venv/bin/python scripts/pi-tool-smoke.py
```

路由 smoke 用简短算术请求验证两个价格档位的真实响应模型不同、普通对话无评分、关闭后保留模型、`/classify` 不执行也不改模型，并检查新会话默认模型未改变。脚本结束恢复原价格偏好，报告保存在 `.runtime/pi-routing-*.report.json`。工具 smoke 检查一次选择贯穿工具请求和后续回答。

北京时间 2026-10-21 实测通过，路由报告为 `.runtime/pi-routing-20261020T173742Z.report.json`：

| 场景 | 实际响应模型 | 验证 |
| --- | --- | --- |
| 希望便宜，路由开启 | deepseek/deepseek-flash | 自动切换，回答 703 |
| 接受昂贵，路由开启 | cirno-gateway/claude-opus-4-6 | 自动切换，回答 703 |
| 路由关闭，价格改回希望便宜 | cirno-gateway/claude-opus-4-6 | 保留当前模型，回答 703 |
| `/classify` 推荐 DeepSeek 后普通输入 | cirno-gateway/claude-opus-4-6 | 分类未切换或执行；后续普通输入才回答 |

共 3 次手动分类、2 次自动选模、4 次真实回答；手动分类均保留 39 个候选、8 个有效价格，普通输入没有评分卡或路由警告，Pi 的新会话默认模型未变。首个手动分类含准备和加载耗时 65.47 秒，后续手动分类约 7.3 秒；不保证冷启动耗时。

工具 smoke 报告 `.runtime/pi-tool-report.json`：实际使用 DeepSeek Flash，一次路由、一次固定 bash 求和、两次 assistant 生成，结果 5050；没有普通评分卡。超长 `/classify` 仍在执行前拒绝。55 项 Node 测试、108 项 Python 测试、Ruff 与 diff 空白检查通过。上述均为功能测试，不代表模型质量/价格收益评估。四类任务、三个价格档位的后续实测与发布记录见 [v0.2.0 版本说明](../releases/v0.2.0.md)。
