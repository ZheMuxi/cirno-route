# 受保护文件与可信模型

自 v0.5.0 起，用户可以指定文件或目录，限制涉及这些文件的 Pi 会话只能使用明确登记的本地模型或可信模型。文件保护优先于能力评分、价格偏好、习惯命中和手动选模；没有符合条件的可用模型时，停止本轮请求。

规则由本地程序判断，不让 Gemma 决定是否可以忽略保护。插件内置的 Gemma 分类器和 E5 匹配模型仍在本机处理任务；执行回答的模型需另外配置并登记，内置分类器不会自动变成 Pi 的回答模型。

## 配置保护范围

在 Pi 中使用以下命令，路径相对于当前 Pi 工作目录解析：

```text
/bakaprivacy add ./private-data
/bakaprivacy add "./documents/private notes.md"
/bakaprivacy status
```

`add` 接受现有文件或目录。添加目录会保护其中的全部文件和子目录，也包括之后新增的文件。路径比较包含规范化路径、符号链接目标与文件身份，避免通过 `..` 或已识别的文件别名直接绕过；目录名相似的相邻目录不会被当作同一目录。

存在目录规则时，具有多个硬链接的文件会被保守地视为受保护文件，即使访问路径在该目录之外。若受保护目录内的符号链接指向目录外的文件，通过该链接访问受保护；但直接从其他路径访问外部目标时，需要将目标文件另行加入保护规则。目录规则不会自动扫描并登记所有外部链接目标。

初始没有保护路径，也没有已登记的可信执行模型。可以先添加路径，再登记允许处理这些文件的模型；登记完成前，相关请求会被拦截。

| 命令 | 行为 |
| --- | --- |
| `/bakaprivacy status` | 查看保护路径、允许的模型及当前会话状态 |
| `/bakaprivacy add <路径>` | 保护一个文件，或递归保护一个目录 |
| `/bakaprivacy remove <路径>` | 移除该路径的规则，不清除已有会话的保护标记 |
| `/bakaprivacy local provider/model` | 显式登记确实在本机推理的执行模型 |
| `/bakaprivacy trust provider/model` | 允许指定模型处理受保护数据，可用于信任的远程服务 |
| `/bakaprivacy revoke provider/model` | 撤销该模型的本地或信任登记 |

## 登记允许的模型

模型必须已配置到 Pi。使用其完整 `provider/model` 标识，例如：

```text
/bakaprivacy local my-local/my-model
/bakaprivacy trust trusted-provider/trusted-model
```

`local` 要求服务端点是回环地址，并表示用户确认该服务实际在本机推理。**回环地址本身不能证明模型在本地运行**：`127.0.0.1` 上的网关可能把请求转发到云端，因此插件不会自动信任所有本机地址。不要把代理云模型的网关登记为本地模型；需要允许它处理受保护文件时，使用 `trust` 明确授权相应模型。

登记同时绑定模型的 provider、模型 ID、API 类型与服务端点。仅名字相同不足以获得许可；更换端点或 API 类型后，需要重新登记。`trust` 只表示用户愿意把受保护内容交给该服务，不证明服务的数据保留或训练政策。

## 路由与拦截

自动路由先排除不允许的执行模型，再在剩余候选中按能力和价格选择。习惯命中也必须指向允许且可用的模型；手动切换到未登记的模型不会解除保护。自动路由关闭后，保护规则仍生效。

`/classify` 仍然只分类、不执行回答；涉及受保护数据时只展示许可候选的评分和推荐。没有许可候选时直接说明无法继续，不退回不可信模型。

文件工具在访问前检查保护范围。内置 `read`、`edit`、`write` 对明确的路径逐项判断；使用不可信模型时，指向受保护文件的操作会被拦截。存在保护规则时，不可信模型的其他工具调用一律阻止，包括目录遍历、shell 和未知工具，因为它们可能通过动态路径读取文件。用户 `!` 和 `!!` 命令也遵守同一限制，不能因为输出只在本地显示就绕过检查。

路径检查兼容 Pi 的 `@` 文件前缀、`~` 用户目录与 Unicode 空格处理；`read` 还检查 Pi 可能使用的 NFD 文件名和弯引号回退路径，避免显示形式不同的路径绕过同一文件的保护。

使用允许的模型执行这类不透明操作时，插件会在执行前保守地标记整个会话为受保护，即使操作没有明确提及私密文件。这意味着启用保护后，一些普通 shell 或目录操作也可能被阻止，或使会话进入保护状态。可以使用已登记的执行模型完成这些操作，不需要临时解除文件保护。

## 模板与系统提示词

通过输入命令使用提示词模板或技能时，插件在内容展开前检查已登记的源文件路径。项目和 Pi 用户配置目录中的 `SYSTEM.md`、`APPEND_SYSTEM.md`，以及命令行 `--system-prompt`、`--append-system-prompt` 指定的文件，也会按保护路径检查，避免文件变成纯文本后丢失来源。

存在保护规则时，若 `systemPromptOptions` 提供没有可靠文件来源的 `customPrompt`、`appendSystemPrompt` 或 `forceSystemPrompt` 文本，插件会保守地将整个会话标为受保护。因此，即使这些自定义系统文本没有读取敏感文件，也可能要求使用已登记的本地或可信模型。

## 会话中的后续内容

会话涉及受保护文件后，会保留保护标记。后续请求即使只写“继续”，或上下文已经压缩为摘要，也仍限制为允许的模型；压缩、重载插件或恢复同一会话不会自动解除标记。

删除路径规则不会让已包含受保护内容的会话重新允许不可信模型。若要继续不涉及这些数据的普通对话，应开启新的空会话，避免把旧会话内容复制过去。

除普通回答外，Pi 的压缩和摘要也可能调用模型。插件针对锁定的 Pi 1.2.0，在最终 provider 发送前再次检查实际模型和端点，普通请求、压缩及摘要遵守同一许可规则。涉及保护规则或已标记会话时，还会停止提示词缓存预热。

## 本地保存

配置路径由 `config/pi-classifier.json` 中的 `privacy_file` 指定，默认是 `.runtime/file-privacy.json`。其中保存路径规则、模型登记及会话保护标记，不保存受保护文件正文或 API 密钥。文件使用仅当前用户可读写的权限，并通过临时文件原子替换保存；规则读取异常、记录损坏或保存锁冲突时拒绝继续相关操作，不把异常当作空规则发送请求。

内置 `write`、`edit` 工具不能修改隐私配置文件及其已识别的别名。请由用户通过 `/bakaprivacy` 命令管理规则，或退出 Pi 后在外部手工调整，不把规则变更交给回答模型执行。

该文件属于本机数据，不进入 Git。Pi 自身的聊天记录仍按 Pi 的配置保存在本机；文件保护不会代替会话存储管理，也不会删除已经保存的历史内容。

## 适用范围

- 必须先添加规则，再让 Pi 使用相关文件。保护不能撤回此前已经发送给模型的数据。
- 规则识别文件来源与路径，不能可靠识别没有来源标记的粘贴内容、另存到未受保护位置的副本，或其他方式产生的衍生文本。敏感副本也应纳入保护目录。
- 保护依赖 CirnoRoute 扩展加载，以及项目锁定的 Pi 1.2.0 内部 `prepareRequest` 接口。发送守卫安装失败时，命令拒绝新增或变更保护配置；若已有保护规则或会话已受保护，插件会停止 Pi，避免退回无拦截的发送。升级 Pi 前需要同步适配。
- 本功能限制本插件所管理的 Pi 模型请求，不是操作系统沙箱，也不控制其他应用或任意扩展自行发起的网络访问。不要把不可信的扩展与受保护会话混用。
- 模型登记信任的是用户配置的服务。服务自身转发到哪里、如何保存收到的数据，需要由用户核实。
