# Gemma 分类提示词对比

本文为 V2 历史记录。当前使用 V3，见 [V3 验证记录](prompt-evaluation-v3.md)。

验证日期：2026-10-14。仅评估本轮任务与候选资料的匹配，不读取历史会话、不提取或更新用户习惯，也不自动切换执行模型。

## 提示词设计

新版文件为 `src/cirno_route/resources/router-system-v2.txt`；原始 `router-system-v1.txt` 保留为对照。

- 根据交付物和实际操作区分编程、语言转换、创作、提取、计算证明、设计分析；`task_type` 和领域关键词不能覆盖正文。例如翻译 Python 文档不等于编程，从小说介绍提取字段不等于创作。
- 采用相同的绝对评分尺度，先判断明确不支持和资料不足，再评估支持程度；避免把候选擅长的辅助工作当成任务核心。
- 简单任务可以并列高分，不奖励任务用不到的复杂推理能力；质量分不混入费用、速度、模型品牌或输入顺序。
- 将配置声明与实测区分，缺少实测本身不是统一扣分或添加 `EVIDENCE_INSUFFICIENT` 的理由。
- 增加边界示例；保留原有候选 ID、证据引用、空偏好和 JSON 合同。

## 对比方法

固定用例在 `evals/prompt-cases/task-fit-v1.json`，共 8 个开发用例和 9 个独立验证用例。合成候选明确限定能力范围，用于检查是否根据操作评分；真实候选卡片直接复制本机配置，用于检查简单任务并列、复杂任务支持程度和资料缺失。未修改真实候选卡片，也未增加模型能力事实。

所有期望在首次推理前确定。开发阶段第一版较长的规则提示词只通过 5/8，出现信息提取与创作混淆，未启用。补充具体边界示例后通过 7/8，随后冻结提示词再运行验证集，没有根据验证结果调参。

新旧提示词使用同一已锁定 Gemma Q4_K_M、llama.cpp `b10516-b95502ba9`、上下文 8192、temperature=0、seed=42、thinking 关闭、最多 1536 输出 token。每个用例串行执行两个版本并交替先后顺序。两组使用相同输入、Schema、重试与校验机制。此次均为单次成对运行，没有多次抽样估计。

通过数表示满足用例中预先写定的比较/弃权期望，同时通过输出合同与空偏好检查；它不是供应商模型的真实任务成功率，也不表示提示词全部语义规则均已满足。顺序与名称变体来自已有验证任务，不是额外的独立任务分布。

## 实测结果

| 检查集合 | 原始 v1 | 冻结 v2 |
| --- | --- | --- |
| 开发用例 | 6/8 | 7/8 |
| 独立验证用例 | 5/9 | 7/9 |
| 合计（含开发用例） | 11/17 | 14/17 |
| 模型输出通过程序合同检查 | 17/17 | 17/17 |
| 格式重试次数 | 0 | 0 |
| 平均单次分类时间 | 9.91 秒 | 10.18 秒 |
| 最大实际输入 token | 1464 | 2380 |

时间是本机此次串行运行观测，受缓存等因素影响，不是性能基准。输入与最多 1536 输出 token 均在 8192 上下文预算内。

部分具体变化：

| 任务/检查 | v1 | v2 |
| --- | --- | --- |
| 简单乘法，Sonnet / Opus / Flash | 3 / 4 / 3；均标资料不足 | 4 / 4 / 4；不再因缺少实测标资料不足 |
| 复杂缓存一致性设计，同上 | 3 / 4 / 2 | 3 / 4 / 2 |
| 表格计算，合成编程 / 写作 / 数据候选 | 3 / 2 / 4 | 2 / 1 / 4 |
| 日志字段提取，同上 | 3 / 2 / 4 | 2 / 1 / 4 |
| 报错信息改写，同上 | 2 / 3 / 1 | 2 / 4 / 1 |
| 编程候选改成误导性模型名称，保留能力资料 | 数据候选由2变1，检查失败 | 4 / 2 / 1保持不变，检查通过 |

实际任务的最高分候选可保持相同，但无关候选的分数下降，体现出更清晰的操作匹配。简单任务合理并列，不追求每个任务都有唯一胜者。

### 已知未解决问题

- 缺少照片的身份识别、无法访问的实时私有数据库，两版本都没有正确弃权；v2 仍分别给出 3/3/3 和 3/4/2。这些是失败案例，不计通过。
- 候选倒序后，报错改写任务的合成数据候选从1变2；最高分写作候选仍为4，但精确分数不变性检查失败。
- 合成卡片已明确不支持某些核心操作，Gemma 仍有给1或2而非0的情况。新版更明确的评分尺度没有完全消除绝对分数校准问题。
- 虽然提示词要求仅有配置声明时至少为 medium，v2 的17个用例仍有5个包含 low（v1为12个）；本次没有通过改写模型结果掩盖这一点。`uncertainty` 不能视为经过校准的置信度。

因此本次启用 v2 的依据是有限固定测试上的改善，不是全部问题已解决。分类仍只展示评分，不承担自动选模或授权决策。后续提升需要更细的候选能力证据和独立任务测量，不能只靠扩大分差。

完整本机报告为 `.runtime/prompt-eval-dev-v2a.json`（未采用的初稿）、`.runtime/prompt-eval-dev-v2b.json`、`.runtime/prompt-eval-validation-v2b.json`；包含各例全部分数、原因码、证据引用、提示词/输入/模型哈希、usage、耗时及失败检查。

## Pi 接入确认

已将生产 `PROMPT_VERSION` 切换至 `router-system-v2`。真实 Pi 加载扩展并完成两次 `/classify`：简单乘法为 Sonnet/Opus/Flash **4/4/4**，复杂缓存设计为 **3/4/2**。两次均来自本地 Gemma，提示词哈希与冻结新版一致，偏好分全部为空，没有执行模型回复。

报告：`.runtime/pi-prompt-v2-report.json`。可运行 `.venv/bin/python scripts/pi-prompt-smoke.py` 复现；需要8045模型目录可用，任务正文只进入本地分类后台。脚本会更新该 Pi smoke 报告与对应日志。

当前 Python 自动化测试70项通过，Ruff 静态检查与格式检查通过。新测试覆盖评估提示词实例隔离及元数据与实际发送内容一致。

已打开的 Pi 执行 `/reload` 或重启即可加载新版；普通输入自动分类仍需 `/bakarouter` 开启。独立 HTTP 分类服务如已运行，需要重启其 Python 进程。

## 复现

在项目根目录运行；自动复用已验证的本地服务或通过现有管理器准备和启动模型。报告包含合成任务的分类输出及运行元数据，写入被 Git 忽略的 `.runtime/`。脚本拒绝覆盖旧报告。

```bash
.venv/bin/python scripts/evaluate-prompts.py --split dev --output .runtime/prompt-dev-new-run.json
.venv/bin/python scripts/evaluate-prompts.py --split validation --output .runtime/prompt-validation-new-run.json
```

评估使用构造时传入的独立提示词实例，不改写全局变量，也不允许 HTTP/JSON 请求覆盖系统提示词。生产入口由 `classifier.py` 中的 `PROMPT_VERSION` 决定。
