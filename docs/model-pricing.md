# 模型价格与价格偏好

Pi 从 v0.6.0 起先计算榜单十分制，再按价格偏好推荐。分项和来源可通过 `/classify` 查看。[榜单评分](benchmark-routing.md)

价格策略用于推荐，也用于开启 `/bakarouter` 后的普通输入自动选模；`/classify` 仍只显示评分和推荐，不执行或切换模型。普通输入隐藏各模型评分，每次回答显示实际执行模型。开关及失败处理见 [自动路由](automatic-routing.md)。本地 [习惯路由](task-habits.md) 按价格档位和实际影响选择的有效价格数据分开累计；没有消费预算管理。

## 使用

重启 Pi 或执行 `/reload`，然后输入 `/bakaprice` 打开三选一菜单；也可以直接输入：

| 命令 | 行为 |
| --- | --- |
| `/bakaprice 希望便宜` | 能力达标时尽量选低价 |
| `/bakaprice 均衡` | 能力差距较小且节省明显时选便宜模型，默认档位 |
| `/bakaprice 接受昂贵` | 优先任务质量，评分相同时选已知价格更高的模型 |
| `/bakaprice status` | 查看当前设置 |
| `/bakamodels` | 只读查看资料与价格状态，不联网、不写文件 |
| `/bakamodels refresh` | 同步官方榜单 |
| `/bakamodels prices` | 更新官方 API 参考价格 |
| `/classify 你的任务` | 查看能力分、各模型价格、当前偏好和推荐依据 |

英文参数分别为 `cheap`、`balanced`、`premium`。RPC/非交互模式下无参数只显示当前设置，不等待菜单操作。设置保存在 `.runtime/router-preferences.json`，重启或 `/reload` 后保留；该文件不进入 Git。此文件只保存用户明确选择的价格档位；习惯记录使用独立的本地文件。

使用 `/bakamodels prices` 手动刷新价格，下次分类会读取新的有效参考价。

## 选择规则

Pi 榜单模式使用 `benchmark-price-v1`。三档规则及覆盖率见[榜单评分](benchmark-routing.md)。以下 `quality-price-v1` 规则适用于旧四分制记录。

- **希望便宜**：在达标且价格有效的候选中取参考成本最低者；同价取能力更高者。没有可比价格时退回能力优先，不将未知价格当免费。
- **均衡**：先取能力最高者，同分取便宜者。仅当便宜候选能力差距不超过 1 级、且成本不到能力最高候选的三分之一时，改选便宜候选。最高能力候选价格未知时不推算节省比例。
- **接受昂贵**：先取能力最高者，同分取已知价格更高者。未知/过期价格不算昂贵；能力更低的模型不会仅因贵而越过能力更高的模型。此同分规则是用户明确选择，不代表价格证明质量。

能力和价格均相同时用稳定 candidate ID 决定显示顺序，避免输入候选换序改变程序选择。推荐模型置顶；其余按能力、对应档位的同分价格规则排列。所有候选保留，包括无价格、能力未知和未达门槛的候选。

例：A 为 4 分、标准比较成本 $0.010；B 为 3 分、$0.002。希望便宜和均衡推荐 B；接受昂贵推荐 A。若 A、B 都为 4 分，前两档推荐 B，接受昂贵推荐 A。

## 价格口径

云模型统一使用对应模型厂商的 **官方 API 参考价，USD / 一百万 token**，分开记录输入、输出及可选缓存读取单价；本地运行模型的 API 费用为 0。比较采用同一工作量：1,000 输入 token + 1,000 输出 token、无缓存命中：

```text
比较成本 = (输入单价 + 输出单价) / 1000
```

这是排序参考，不是本次对话账单。当前不预测回答长度，不计算历史/工具上下文、思考 token、各家 tokenizer 差异、搜索费用、时段/批量折扣和税费，也不把套餐费分摊到每个请求。长输入或长输出任务的实际成本排序可能不同。DeepSeek 使用高峰标准价；缓存单价仅记录，暂不参与排序。

每条价格包含 `source`、来源 URL、UTC 核对日 `checked_at`、UTC 有效期 `valid_until` 和备注；自动资料还可带精确到秒的 `expires_at`。来源类型如下：

- `official`：直接调用供应商的公开标准价。
- `reference`：通过其他渠道调用的模型采用其厂商官方 API 参考价，参与路由比较；不代表该渠道真实收费或已验证后端身份。自动记录同时保存 `pricing_basis: "official_api"`、`reference_provider` 和 `reference_model`，说明价格对应的厂商与型号。
- `user`：用户根据实际渠道填写的价格。
- `local`：与当前执行端点相符的本机推理登记，API token 费用为 0，不代表电费、内存或硬件成本。

按完整 `provider/model` 精确匹配，不把基础型号价格套到 thinking/high/low 等后缀，也不从 Pi 未配置价格时显示的零推断免费。缺失、明确为 null、过期或未来日期均不参与价格比较；有效的显式零价或匹配的本地登记才按零计算。仅接受 USD，避免静默混用人民币和美元；只有人民币报价且未核实美元标准价时保留未知。

### 自动资料与手动价格

| 文件 | 用途 |
| --- | --- |
| `config/model-prices.json` | 手动价格基础表，联网查询不覆盖 |
| `.runtime/model-prices.researched.json` | 自动查询价格表，原子写入，不进入 Git |

两条路径由 `config/pi-classifier.json` 的 `pricing_file` 和 `researched_pricing_file` 指定，相对路径以该配置文件所在目录为基准。默认分别为 `model-prices.json` 和 `../.runtime/model-prices.researched.json`。

`/bakamodels prices` 按官方来源独立核对价格。有效的用户配置价格优先。查询失败时继续使用仍在有效期内的旧价，过期资料保持未知。

程序优先从已获取的官方表格直接提取价格，核对准确型号、输入/输出/缓存列、计价单位及适用档位。即使研究模型改写了引文，也先检查原始表格；无法确认或出现冲突时保持未知，不让模型自行裁定哪一组数字正确。

当前自动查价支持 OpenAI、DeepSeek 和 OpenCode Go，其他渠道可填写手动价格。能力缓存仍有效而价格需要更新时，只重查价格；这会产生搜索和整理调用，按重试间隔执行，不在每次分类时反复查询。

修改价格偏好或手动价格不要求重查能力缓存。下一次分类使用最新有效价格表；价格独立于能力证据，三档价格偏好仍由程序处理。仅更新核对日期、来源或备注等不影响选择的资料，不会重置习惯。只有当前候选的有效单价、计费状态等影响选模的数据发生变化，才切换习惯记录的适用范围；例如价格过期而失去可比性，与延长有效期但价格仍相同是不同情况。

### 提供给本地分类器的价格格式

能力查询及价格同步完成后，程序读取一次有效价格快照，按当前批次的候选 ID 发送。默认紧凑模式示例（数字仅用于说明格式）：

```json
{
  "pricing_context": {
    "currency": "USD",
    "unit": "per_million_tokens",
    "columns": ["id", "status", "basis", "input", "output", "cache_read"],
    "rows": [
      ["c0", "known", "official_api", 0.3, 1.2, 0.006],
      ["c1", "known", "local", 0, 0, 0],
      ["c2", "unknown", "unknown", null, null, null]
    ]
  }
}
```

- `id` 与同一批能力卡片的 `c0`、`c1` 对应，不是能力证据 ID；币种与单位只写一次。
- `status` 为 `known`、`unknown` 或 `stale`。未知或过期单价统一为 `null`，不能当作免费。
- `basis` 为 `official_api`、`user`、`local` 或 `unknown`。云模型使用官方 API 参考价，有效手动配置保留为 `user`，明确绑定的本地模型三项均为 `0`。
- 输入、输出、缓存读取均按每百万 token 计价，保留原始数值；缓存读取未知时为 `null`。网址、长篇备注、核对日期、模型名称及凭据不进入此表。

价格说明明确要求 Gemma 不因贵而加能力分、不因免费而减分；价格字段不能作为能力证据引用。这是评分约束，不能保证新增上下文后所有任务的分数都完全不变。价格表计入字节和实际 token 预算，拆批时只保留该批对应的行，不删候选。关闭紧凑模式后使用含 `candidate_id` 和完整单价字段名的对象，含义相同。旧客户端不传 `pricing_context` 时保留原请求格式。

能力卡片哈希不随价格变化；独立的 `pricing_context_sha256` 记录价格上下文，`model_input_sha256` 记录实际输入。只更改价格偏好不会更改 Gemma 价格表。

### OpenCode Go 使用官方 API 参考价

OpenCode Go 的候选按明确型号映射到模型厂商，从厂商官方来源查询 API 价格；有效资料显示为 `known`、`source: "reference"`，与其他云模型一起参与“希望便宜／均衡／接受昂贵”的选择。官方价格也不作为能力评分依据。

不采用套餐月费、月度额度、套餐折扣或套餐内某次零扣款；旧 `subscription` 记录及其 `reference_*_per_million` 字段不能直接转成官方 API 价格，升级后会显示待更新并重新查价。尚未确认对应型号、区域、单位或适用条件时仍保留未知。

参考价统一采用适合 1k 输入的标准上下文档位。涉及地区差异时记录固定基准，例如千问采用国际站 Singapore 档、腾讯采用国际站目录价；明确的未来调价会缩短价格有效期。此处改变的是插件的比较依据，不会改变服务商的订阅、扣费方式或超额设置，也不是实际消费预算控制。

### 本地模型 API 零价

在 `config/pi-classifier.json` 中明确登记本地执行模型，例如：

```json
{
  "local_price_models": [
    {
      "provider": "cirno-local",
      "model": "cirno-gemma-e4b",
      "base_url": "http://127.0.0.1:18080/v1"
    }
  ]
}
```

模型完整 ID、回环地址必须与 Pi 当前目录中的执行入口相符；地址变更后旧绑定不再提供零价。已通过 `/bakaprivacy local provider/model` 登记的本地模型也可提供绑定。单独填写 `source: "local"` 或使用 `localhost` 地址不足以证明本机推理，因为本机地址也可能是收费云服务代理。

价格登记只负责计费口径，不授予受保护文件访问权限；隐私许可仍通过 [文件保护](file-privacy.md) 单独设置。内置 `node-llama-cpp` 分类器与 Pi 的 HTTP 回答入口仍是不同用途，零价不代表对应回答服务已经启动或可用。

## 初始资料

以下为手动基础表的历史初始资料，并非当前自动查询覆盖情况。北京时间 2026-10-21 核对官方页面（文件使用 UTC 日期，核对日为 2026-10-20），初始有效期设到 2026-11-20。2026-11-11 删除 `cirno-gateway` 全部模型后，手动表只保留以下 2 个 DeepSeek 完整 ID；当时 OpenAI、OpenCode Go 和本地入口尚无路由价格条目。移除条目没有重新核验以下价格。现在运行时会合并有效自动资料及本地绑定；历史表到期后不会继续作为有效价格。

| Provider / 模型 | 输入 / 输出，USD 每百万 token | 类型 |
| --- | --- | --- |
| deepseek / deepseek-flash | 0.30 / 1.20 | 官方高峰标准价 |
| deepseek / deepseek-v4-pro | 1.32 / 3.96 | 官方高峰标准价 |

来源：[DeepSeek 定价](https://api-docs.deepseek.com/quick_start/pricing/)。

编辑价格时使用你的实际渠道费率，保留完整 provider/model 键，修改输入/输出价格、`source: "user"`、核对日、有效期和备注。确认模型免费时需显式填写两个 0；不能确认则删除对应条目或将两个价格都设为 null。不要把 API 密钥写入这个文件。

损坏的价格文件或偏好文件会返回固定错误码，不把错误数据用于推荐；普通 Pi 对话仍可继续使用当前模型。
