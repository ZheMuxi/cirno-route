# CirnoRoute v0.4.0 版本说明

- 发布日期：2026-11-11。
- 版本标签：`v0.4.0`。
- 前版、对比基线与源码回退目标：`v0.3.0`；原标签保留。

本次增加按任务类型累计模型使用次数的习惯路由，并将轻量多语言语义模型集成到 Pi 插件。当新任务与已有习惯足够匹配时，插件直接选择习惯模型回答，省去本轮 Gemma 分类；其余任务继续走原有的能力评分与价格路由流程。

## 新增按使用次数形成的习惯路由

默认累计门槛为 **5 次**，可由用户调整。同一任务分组内，某个模型的成功使用次数达到门槛，且严格高于其他模型时，才具备成为习惯模型的条件。次数并列时不直接选定习惯模型。

计数来源包括用户显式手动选择的模型，以及 Gemma 自动路由后实际完成回答的模型。习惯命中后直接使用模型的回答，不增加使用次数，也不增加语义样本，避免命中行为持续强化自身。

计数在回答结束后进行，核对实际使用的 provider/model、结束状态和非空文本。报错、中止、截断、工具失败、回答过程中换模，以及混入多个用户请求的回合不计入；同一回合的工具续传不重复累计。

当习惯学习开启时，用户手动换模会优先用于下一轮回答；若自动路由处于开启状态，此轮结束后后续输入恢复自动路由。现有聊天记录不会自动导入习惯库，首次使用从零开始累计。

## 增加任务类型与语义匹配

任务分组同时考虑操作类型、难度和必要能力。例如，程序实现与代码解释、数值计算与数学证明分别处理；联网、工具操作、长上下文和严格结构化输出等要求也参与分组。

两条学习路径采用不同的任务识别方式：

- **手动选模路径**：使用轻量规则识别明确操作；规则无法可靠判断或材料不足时，跳过学习。
- **Gemma 自动路由路径**：在原评分的同一次生成中附带 `task_profile`，不使用轻量规则预分类。候选分批时只由第一批生成任务标签，其余批次继续评分。

任务标签包含类型、难度、必要能力以及是否适合复用。标签无效时仅放弃习惯学习，保留有效的模型评分和路由结果。

新增的 `multilingual-e5-small` 使用 ONNX INT8 权重，在本地生成 384 维向量，用于比较新任务与已保存任务样本的语义相似度。它负责匹配任务，不生成回答，也不替代 Gemma 的能力评分。

习惯匹配默认要求：

- 与最接近分组的相似度至少为 **0.985**。
- 与第二接近分组的相似度差距至少为 **0.04**。
- 分组内存在达到累计门槛的唯一领先模型，且该模型当前可用。

尚未达到累计门槛的其他分组也参与歧义判断。匹配不确定、习惯模型不可用或语义处理失败时，继续原有 Gemma 路由。语义输入上限为 **512 token**；超过上限不截断输入，而是交回 Gemma，并跳过该任务的习惯学习。

## 将语义运行时内置到插件

新增插件私有的语义运行时，通过本地子进程与管道通信，不监听 HTTP 端口，无需用户另外启动模型应用。

首次需要语义向量时，插件下载固定版本的 E5 文件，并按清单核对文件大小与 SHA-256。必需文件合计约 **135.4 MB**，其中 ONNX 权重约 **118.3 MB**；下载大小与运行内存是不同指标。后续语义推理复用本机缓存，任务正文只在本地语义处理链路中传递。

安装入口同步增加语义运行时依赖：新安装由 `scripts/install-pi.sh` 一并处理；已有安装可使用 `scripts/install-semantic-runtime.sh` 补齐依赖。提交任务时不会自动执行 npm 安装，依赖缺失会给出提示，并保留原 Gemma 路由。

依赖由独立锁文件固定，包括 `onnxruntime-node 1.21.0`、`@huggingface/tokenizers 0.2.0` 和用于兼容入口的 `tokenizers 0.23.2`。

## 优化 E5 内存与进程生命周期

默认分词器改为紧凑实现，保留完整的 **250,002 个词条**、原有词条分数、特殊 token 和模型 Unicode 归一化数据，以紧凑词表检索替代大型对象树。

此次优化还包括：

- 分词器加载后回收解析临时对象，减少其与 ONNX 加载期间的内存叠加。
- 复用 ONNX 推理缓冲区，关闭按输入形状保留的内存模式缓存。
- 在 macOS 上仅为语义子进程设置内存分配优化，并尊重用户已有的显式设置。
- 按需启动语义进程，空闲 **15 秒**后释放；退出或重载 Pi 时清理所属进程。
- 退出时等待原生线程释放资源，减少进程结束阶段的资源冲突。

优化保留多语言词表、INT8 权重和 512 token 输入上限。原生分词器兼容入口通过 `CIRNO_SEMANTIC_TOKENIZER=native` 启用，现有习惯记录可继续使用。

## 新增习惯管理命令

| 命令 | 作用 |
| --- | --- |
| `/bakahabits` 或 `/bakahabits status` | 查看学习开关、累计门槛、分组数和成功使用总数 |
| `/bakahabits on` | 开启习惯学习与匹配 |
| `/bakahabits off` | 停止学习与匹配，释放语义进程；自动路由开启时恢复逐轮 Gemma 分类 |
| `/bakahabits threshold 5` | 设置累计门槛，支持 1–1000 次 |
| `/bakahabits prepare` | 提前下载并加载语义模型 |
| `/bakahabits clear` | 清空习惯记录，或显式重建损坏、不兼容的记录文件 |

习惯学习初始配置默认开启，自动选模仍需用户输入 `/bakarouter` 开启。习惯开关与门槛保存在本地，已保存的用户设置优先于配置文件中的初始值。

`/bakarouter off` 只关闭自动选模；习惯学习开启时，手动选择模型后的成功回答仍可累计。需要同时停止学习和匹配时，使用 `/bakahabits off`。

`/classify` 始终单独进行分类，展示评分和推荐，不命中习惯、不切换回答模型、不执行回答，也不学习习惯。普通对话继续隐藏评分并显示实际回答模型；习惯命中时额外提示对应类型和模型。

## 按价格与候选范围隔离习惯

习惯记录除任务类型外，还关联价格偏好、价格表和模型目录／端点的指纹。

“希望便宜”“均衡”“接受昂贵”分别累计，不互相套用记录。价格表、价格有效状态、候选模型或端点变化后，旧范围的记录保留，但不会直接用于新的范围。

手动选模记录反映用户在该价格偏好下的实际选择，因此可能不同于价格算法的推荐。能力研究资料刷新不会自动重算已有习惯；需要重新学习时可以清空记录。

## 增加本地习惯存储与异常处理

记录默认保存到 `.runtime/task-habits.json`，内容包括模型使用次数、任务类型、任务哈希和语义向量，不保存任务原文或 API 密钥。语义向量属于个人任务衍生数据，保留在本机。

每个分组最多保存最近 **8 个不同任务**的向量样本，最多保留 **128 个分组**；达到分组上限后提示并停止新增分组。

保存采用进程锁和临时文件原子替换，文件权限限制为仅当前用户读写，并记录回合标识以防止重复计数。记录损坏或不兼容时停止学习与匹配并提示，不静默覆盖原文件。模型缓存、运行数据和习惯记录不纳入 Git 版本管理。

这些存储限制适用于新增习惯库；正常回答仍按用户配置交给选中的回答模型处理。

## 安装与启用

需要 Python 3.12 或更高版本、uv、Node.js 22.19.0 或更高版本、npm 和 Git。选择任意有写权限的工作目录，保留源码目录名 `cirno-route`；安装脚本会在其同级创建 `Pi`。

首次安装：

```bash
git clone https://github.com/ZheMuxi/cirno-route.git
cd cirno-route
git switch --detach v0.4.0
uv sync --frozen --python 3.12
./scripts/install-pi.sh
.venv/bin/cirno-route init
```

随后按 [通用配置说明](../README.md#配置自己的模型服务)填写自己的模型服务、凭据和研究配置。仓库中的服务地址与模型目录属于模板，需与实际可用服务一致；密钥只保存在本机配置中。完成配置后运行：

```bash
./scripts/start-pi.sh --model your-provider/your-model
```

将 `your-provider/your-model` 替换为自己已配置的回答模型。进入 Pi 后可先执行 `/bakahabits prepare` 提前准备语义模型，再使用 `/bakarouter` 开启自动路由；习惯尚未形成时仍由 Gemma 分类。

已有安装升级时，先退出 Pi，并保存本地未提交改动。保持工作区干净后，从仓库根目录执行：

```bash
git fetch origin --tags
git switch --detach v0.4.0
uv sync --frozen --python 3.12
./scripts/install-pi.sh
```

安装脚本保留现有 Pi 配置和会话。若此前自行修改了分类配置，需要保留自己的设置，并将本版 `config/pi-classifier.json` 的 `habits` 配置合入本机配置；不要用模板覆盖凭据或服务地址。

## 适用边界

本次属于按使用次数形成的任务习惯，不包含满意度判断、反馈纠错、时间衰减、用户画像或模型微调。正常完成的回答即使内容有误，也可能计入使用次数。

E5 相似度和 Gemma 任务标签都可能出错。缺少必要材料时，Gemma 仍可能给出评分，或将任务错误标为可复用；类型标签不代表材料完整性已被可靠确认。严格匹配门槛会放弃部分跨语言等义任务，以及主题不同但操作相同的任务；这些任务继续进入 Gemma 分类。新增任务标签会改变学习路径中的完整输入，不保证所有评分都与未开启习惯时完全相同。

Pi 当前接口无法区分用户手动换模与其他扩展发起的部分换模操作；并用多个自动选模扩展时，这些操作可能被视为手动选择。

本次功能建立在已有的 Gemma 4 E4B、0–4 分制、V2.1 评分标准、默认 `node-llama-cpp` 后端和三档价格路由之上；这些基础能力属于此前版本。

## 关闭功能与回退

只需关闭习惯路由时，在 Pi 输入 `/bakahabits off`。也可退出 Pi 后从仓库根目录运行：

```bash
CIRNO_HABITS=0 ./scripts/start-pi.sh
```

这会完全禁用习惯服务，保留原有 Gemma 分类、价格路由和已有习惯记录。

若要将源码与依赖一起回退到 `v0.3.0`，先退出 Pi，停止本项目自行启动的独立服务，保存未提交改动，并确认 `git status --short` 没有输出。然后执行：

```bash
git fetch origin --tags
git switch --detach v0.3.0
uv sync --frozen --python 3.12
./scripts/install-pi.sh
./scripts/start-pi.sh
```

`v0.3.0` 不读取习惯文件，回退无需迁移或删除习惯记录。模型缓存、价格偏好、服务凭据与 Pi 会话仍保留在本机。不要使用 `reset --hard` 或 `clean` 丢弃尚未保存的改动，也不要覆盖旧标签。

返回本版时，退出 Pi 后执行：

```bash
git switch --detach v0.4.0
uv sync --frozen --python 3.12
./scripts/install-pi.sh
./scripts/start-pi.sh
```

切换版本后重新启动 Pi，并按需输入 `/bakarouter`。更多版本管理约定见 [版本与回退](../docs/versioning.md)。
