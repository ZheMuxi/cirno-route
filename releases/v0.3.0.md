# CirnoRoute v0.3.0 版本说明

- 日期：2026-10-28。
- 版本标签：`v0.3.0`；前版及完整回退目标：`v0.2.0`。
- 本版重点：V2.1 任务适配评分标准，以及默认使用插件内置的 `node-llama-cpp` 后端。
- 继续使用 Gemma 4 E4B Q4_K_M、0–4 分制和每批一次分类；不包含用户习惯自适应、微调或预算管理。

## 本版完成的工作

### 1. 优化本地分类评分标准

新增 `router-system-v2.1.txt`，从任务交付物、核心操作、实际难度和关键约束判断模型适配程度。

- 收紧 3 分与 4 分的边界：4 分要求正向证据覆盖相当难度和全部关键要求。
- 强调核心能力短板，区分明确不支持、资料不足和一般能力支持。
- 简单任务允许合理并列，不将品牌、价格或能力描述篇幅当成质量依据。
- 保留原 V2 提示词和单次分类流程，没有恢复 V3 多阶段推理。
- 评测入口支持 `--versions v2 v2.1`，元数据记录实际提示词版本与哈希。

提示词对照的详细样本口径与失败记录见 [提示词评测](../docs/prompt-evaluation.md)。

### 2. 将原生推理库集成到插件，设为默认后端

`node-llama-cpp` 依赖安装在插件自己的目录，通过独立 npm 锁文件固定。Pi 启动后，第一次分类自动加载现有 Gemma 权重，不需要另外启动模型应用。

运行链路为 Pi → Python 分类校验 → 私有 Node worker → llama.cpp 原生库。新后端不启动 `llama-server`、不监听推理 HTTP 端口；Python 继续承担能力研究、输入输出校验和原有分类逻辑。

- 默认入口 `start-pi.sh`、Pi 扩展及分类 worker 均使用原生后端。
- `install-pi.sh` 同时安装原生依赖；已有安装可单独执行 `install-native-runtime.sh`。
- `start-pi-native.sh` 保留为显式原生入口，新增 `start-pi-llama.sh` 用于选择旧后端。
- 模型文件沿用现有检测、缓存、下载与 SHA-256 校验，不重复打包或上传权重。
- 每次分类建立独立逻辑会话，复用加载的模型及共同 token 前缀；不把前一个任务作为历史加入新任务。
- 支持紧凑和完整输出协议，保留候选 ID、证据、分数范围与上下文预算校验。
- 正常退出、取消、超时和父进程异常退出会清理所属进程。
- 手动分类显示原生后端标识，审计记录实际运行时版本；普通对话继续只显示实际回答模型，不展示候选分数。

新后端失败不会静默切到旧运行时。Pi 原有的分类失败处理保持不变，普通对话可能继续用当前模型回答。实现与限制见 [原生后端说明](../docs/native-runtime.md)。

## 验证结果与适用范围

开发阶段已完成以下实测，原始临时文件已清理，仅保留脱敏摘要：

| 检查 | 结果 |
| --- | --- |
| V2 → V2.1 验证检查 | 20/29 → 22/29；包含变体，不是 29 个独立任务 |
| 9 项扰动与重跑一致性 | 7/9 → 9/9；限本次固定分组和运行环境 |
| 新旧后端固定 17 用例输出合同 | 两者均 17/17 |
| 新旧后端任务评分预期 | 两者均 16/17，保留同一个已知失败 |
| 四个任务重复评分 | 两者均 4/4 一致 |
| 17 次紧凑分类平均耗时 | 旧后端 2.76 秒；原生后端 2.55 秒 |
| 完整协议示例耗时 | 旧后端 13.62 秒；原生后端 16.05 秒 |
| 真实 Pi 手动分类 | 39 个候选全部保留，12 个有资料、27 个未知，2 批 |
| Pi 编程 / 写作分类耗时 | 原生后端约 28.42 / 25.27 秒，包含插件端准备开销 |
| 生命周期 | 正常退出、取消、父进程强制退出均回收所属进程；原生 worker 无 TCP 监听端口 |

真实 Pi 测试使用冻结能力资料，未联网刷新、未调用回答模型。两种后端使用不同 llama.cpp 版本、模板封装和语法实现，17 个用例中有 1 个次要候选评分相差 1 分，首选不变。不将小样本耗时差异视为普遍加速，也不声称内存占用下降。

发布前复验结果：111 项 Python、57 项 Node 测试及 Ruff、脚本语法检查通过，`uv sync --frozen` 与原生依赖按锁文件重装成功。不设置后端参数时，固定用例的输出合同仍为 17/17、任务评分预期为 16/17；真实 Pi 确认默认使用 `node-llama-cpp`，39 个候选分 2 批，编程分类约 28.75 秒，未调用回答模型，退出后进程清理成功。显式选择旧后端的真实分类也通过。

提交文件及可达 Git 历史经过已知凭据与常见密钥格式扫描，未发现密钥；模型权重、运行缓存和测试临时文件不纳入发布。GitHub Checks 通过后合入主分支，再为通过主分支检查的提交建立固定标签；远端 CI 结果以对应 PR 和提交页面为准。

## 已知限制

1. `validation-unknown` 仍未按预期弃权：缺少私有数据库名称和访问条件时可能继续评分。两种后端均存在此问题，本版保留原始测试预期与失败记录。
2. 其他边界仍可能出现明确不支持却给 1–2 分、未知能力给 0 分，以及 configured 证据的不确定性过低。
3. 新运行时和评分优化都不能保证所有任务更快或更准确；跨批次、设备和运行时评分尚未校准。
4. 原生后端主要在 macOS Apple Silicon 上实测；缺少预编译库的平台不会自动编译。旧服务端仍可显式使用。
5. 联网能力资料不是本地实测表现；价格比较不是实际账单。没有新增用户习惯学习、安全外发拦截或预算账本。

## 使用与回退

已有安装升级后，从仓库根目录运行：

```bash
uv sync --frozen --python 3.12
./scripts/install-native-runtime.sh
./scripts/start-pi.sh
```

Pi 中 `/classify 任务内容` 只分类；`/bakarouter` 开启普通输入自动选模回答。

只切回旧推理后端、保留 V2.1 评分标准：退出 Pi 后运行 `./scripts/start-pi-llama.sh`。

完整回退代码和评分标准：先退出 Pi，确认工作区没有未保存改动，然后执行：

```bash
git fetch origin --tags
git switch --detach v0.2.0
uv sync --frozen --python 3.12
./scripts/start-pi.sh
```

旧标签不覆盖、不移动。密钥、模型权重、会话与本地缓存不进入 GitHub，也不随源码回退删除。返回本版使用 `git switch --detach v0.3.0`，同步 Python 依赖并重新执行原生依赖安装。更多约定见 [版本与回退](../docs/versioning.md)。
