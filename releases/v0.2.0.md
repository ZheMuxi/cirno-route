# CirnoRoute v0.2.0 版本说明

- 发布日期：2026-10-21（Asia/Shanghai）。
- 版本标签：`v0.2.0`；前版及回退目标：`v0.1.1`。
- 项目范围：本地任务能力分类、模型能力资料查询、价格偏好及 Pi 自动选模回答。
- 继续使用 Gemma 4 E4B Q4_K_M 和 V2 评分规则；不包含用户习惯学习、画像、自适应权重或消费预算管理。

## 本版完成的工作

### 1. 查询并保存模型能力资料

首次分类前，对 Pi 当前可用模型查询能力资料，默认研究模型为 DeepSeek-V4.1-Flash，对应配置 ID `deepseek-flash`。研究模型、接口和凭据来源可以自行配置。

资料记录模型标识、能力维度、证据来源、查询时间和提示词哈希，并保留不可覆盖的快照。有效资料按缓存复用；无法确认型号时保留未知，不凭名称编造能力分。新增 `/bakamodels` 查看资料状态、`/bakamodels refresh` 主动重新查询。

联网研究只接收模型标识，不接收用户的分类任务。开启实际路由后，用户任务会正常发送给选中的回答模型；本地分类不等于整轮对话都离线。

### 2. 压缩分类上下文，容纳完整候选目录

保持 `router-system-v2.txt` 原文，新增 `compact-v1` 传输格式：短候选 ID、共享重复说明、紧凑结果数组。程序恢复完整结果后继续校验公开输出合同。

保留完整任务、能力证据和限制；候选按稳定 ID 排序，默认每批最多 8 个，并按实际 token 预算二分，不截断或静默丢弃候选。每次推理只传当前任务和资料，不附带上轮分类历史；Gemma 进程保持加载，复用权重及 llama.cpp 上下文缓存。

本机目录实测保留 39 个候选，其中 12 个有能力依据、分 2 批推理，其余 27 个明确未知。候选和资料数量是本次配置的快照，不是发布版本硬编码的模型清单。

### 3. 加入价格资料与三档偏好

新增 `config/model-prices.json` 和 `/bakaprice`。价格按完整 `provider/model` 匹配，记录来源与有效期；未知或过期价格不视为免费或昂贵。价格在 Gemma 评分后由程序处理，不增加分类上下文或推理次数。

| 偏好 | 选择规则 |
| --- | --- |
| 希望便宜 | 在有证据且能力达到 3/4 的候选中优先低价 |
| 均衡 | 优先能力；能力差距不超过 1 级且成本节省超过三分之二时，才改选便宜候选 |
| 接受昂贵 | 优先能力；同分时选择已知价格更高的候选 |

参考成本统一按 1,000 输入 token + 1,000 输出 token、无缓存计算，不代表真实账单。初始价格覆盖 8 个模型 ID；网关使用官方参考价，不代表网关实际收费。偏好是用户明确选择的单项设置，保存在本机并跨重启保留。

### 4. 将推荐结果接入 Pi 实际路由

`/bakarouter` 开启后，普通输入先由 Gemma 评分，再结合价格偏好选择模型并实际回答。`/bakarouter off` 关闭后停止自动选择，保留当前选中的模型。

- `/classify` 始终只显示分类及推荐，不切换模型、不执行任务。
- 每轮用户输入只选一次，工具续传沿用模型。
- 切换前检查 Pi 注册表和网关可用性；失败保留当前模型并提示。
- 关闭开关、改价格偏好或手动换模型会使在途选择失效；若切换后无法恢复原模型，停止本轮回答。
- 普通对话不显示或保存评分卡；根据实际 assistant 响应显示本次使用的 `provider/model`。
- 开关每次启动默认关闭，不改 Pi 新会话的默认回答模型。

### 5. 完善版本记录

统一 Python 项目、模块、Pi 插件和锁文件的项目版本为 `0.2.0`。保留 Pi 1.2.0 的现有依赖锁，加入提交授权约定，更新功能文档、CHANGELOG 和回退步骤。密钥、GGUF、会话、运行日志和本机能力缓存不进入仓库。


| Pi 命令 | 用途 |
| --- | --- |
| `/bakamodels` | 查看模型资料状态 |

## 验证结果

### 四类任务 × 三档价格偏好的真实 Pi 测试

测试日期为 2026-10-21。每组使用独立 Pi 会话，同一任务的三个档位使用完全相同的输入，复用同一 Gemma 后台进程及有效能力缓存。共 12 组真实调用，推荐与实际回答模型全部一致，没有分类警告；普通对话没有评分条目，实际模型标识全部正确。

- 希望便宜与均衡：四题均选择 `deepseek/deepseek-flash`。
- 接受昂贵：四题均选择 `cirno-gateway/claude-opus-4-6`。
- 下表为“分类耗时 / 从提交任务到完整回答的总耗时”，单位秒。

| 任务 | 希望便宜 | 均衡 | 接受昂贵 |
| --- | ---: | ---: | ---: |
| 编程：LRUCache | 23.1 / 25.9 | 6.5 / 9.6 | 6.6 / 17.9 |
| 写作：咖啡店开业文案 | 6.5 / 7.7 | 18.6 / 20.0 | 6.7 / 47.3 |
| 数学：证明 30 整除 n^5−n | 6.6 / 8.5 | 6.5 / 8.6 | 18.2 / 33.0 |
| 简单问答：法国首都 | 18.2 / 18.8 | 6.6 / 7.3 | 6.5 / 9.0 |

每组只测一次，且交错运行不同档位。新题分类约 18–23 秒，重复题命中更多 llama.cpp 上下文缓存后约 6.5–6.7 秒；速度差异不能归因于价格档位。首个编程样本包含进程加载。写作昂贵档的 47.3 秒中，远端响应阶段占 40.7 秒。以上不包含首次联网建立能力资料的时间。

答案复核：

- 三份 LRU 实现各通过 8,000 次独立操作测试，覆盖覆盖更新、读取刷新、淘汰和零容量。
- 三份数学证明正确，未直接引用费马小定理；简单问答均正确输出“巴黎”。
- 写作要求 120–160 字：便宜档 111 字、均衡档 117 字，未达标；昂贵档 125 字，达标。因此这里只能声称路由链路全部通过，不能声称全部回答质量通过。
- 四题中 DeepSeek 均获得 4 分且价格低，便宜与均衡选择相同；本组没有通过真实调用覆盖均衡档“牺牲一级能力换取大幅节省”的分支，该分支由自动化测试覆盖。

该轮临时脚本、配置、会话和日志已全部清理。此处按用户本次授权保存版本摘要，不重新创建原始测试文件。

## 已知限制

1. V2 在缺少必要任务资料时仍可能给出评分；上一阶段紧凑格式固定评测为 15/17，两项失败为 `dev-unsupported`、`validation-unknown`。候选排序和分批后的评分尚未全面校准，不宣称已解决全部顺序敏感问题。
2. 能力研究依赖公开资料和研究模型，可能整理错误；27 个未知候选在本次测试中未参与有依据的选模。资料过期后需要重新查询。
3. 0–4 分不是任务成功概率。写作字数失误说明最高档评分仍无法保证严格约束遵循；低价与均衡档在当前样本中区分不明显。
4. “接受昂贵”按用户要求同分选高价，因此简单问答也会选择 Opus，本次没有体现额外质量收益。
5. 价格排序不预测答案长度、历史及工具上下文、思考 token 或网关套餐，参考成本不是账单。
6. 新任务仍需约 18–23 秒分类；远端响应可能成为更大的总耗时来源。不以缓存样本承诺所有请求都在 7 秒内完成。
7. 本版没有用户习惯自适应。价格偏好仅来自用户显式选择。

## 回退到前一版本

先退出 Pi，确认没有需要保留的未提交改动；有改动时先保存现场，不使用 `reset --hard` 或 `git clean`。

```bash
cd /Users/zhemuxi/CirnoRoute/cirno-route
git status --short
git fetch origin --tags
git switch --detach v0.1.1
uv sync --frozen --python 3.12
/Users/zhemuxi/CirnoRoute/Pi/pi-classifier
```

`v0.1.1` 与本版均使用 Pi 1.2.0，现有安装可以复用；回退后 `/bakarouter` 恢复为仅分类，不自动换模型。密钥、能力缓存和价格偏好保留在本机，不删除或随源码切换。

返回本版用 `git switch --detach v0.2.0`，再执行 `uv sync --frozen --python 3.12` 并重启 Pi；返回日常开发分支用 `git switch main`。`v0.1.1` 和更早的 `v0.1.0-v3-baseline` 标签继续保留，不覆盖或移动。
