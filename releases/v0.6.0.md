# CirnoRoute v0.6.0 修改报告

本版将 Pi 的模型推荐从四档适配等级改为按任务计算的十分制能力分。Gemma 4 E4B 在本机判断任务需要什么能力，程序用公开榜单计算各候选的分数，再结合文件保护、模型可用性和价格偏好选模。

## 榜单从哪里来

| 来源 | 接入方式 |
| --- | --- |
| Arena Text、WebDev | 自动同步官方数据集的 `latest` 分组，分别用于语言任务和网页开发。[官方数据集](https://huggingface.co/datasets/lmarena-ai/leaderboard-dataset) |
| Epoch AI | 自动读取官方数据包中的七个原始分项，覆盖数学、推理、编程和知识问答。[官方数据包](https://epoch.ai/data/benchmark_data.zip) |
| LiveBench 2.0、SuperCLUE、AI 十项全能 | 导入带来源和版本的官方快照，导入成功后参与评分。[快照格式与示例](../docs/benchmark-routing.md) |

Pi 启动时会在后台检查距离上次检查已满 24 小时的自动来源。新数据通过校验后才替换本地快照。下载或读取失败时会显示受影响的来源，并尽量沿用已有有效成绩。数据来源排除 Artificial Analysis 及转载其成绩的记录。

## 分数和推荐怎样产生

- **按任务选分项。** 做 React 界面时使用 Arena WebDev 的 React 分项，做数学证明时使用相应的数学分项。具体型号、推理档位和评测环境随原始成绩一起保留。
- **按固定参照打分。** 每个分项用带版本的参考模型组换算为 0–10 分，显示一位小数。单项任务占 100%，双项任务主次能力分别占 70% 和 30%。同一次评测只计一次。`/classify` 可查看分数、依据和缺项。分数表示模型在参考组中的相对位置。
- **资料不足才补查。** 已上榜的型号只补当前任务缺少的分项。各榜均查无该型号时查询其公开资料。相关榜单读取失败时补查受影响的部分。同一缺项合并查询并复用缓存。只有厂商功能说明时标为「资料推定」，作为候补，能力分保留未知。
- **价格单独比较。** 先筛选文件保护允许、当前可用且满足硬性要求的模型，再比较成绩覆盖率、能力分和价格。「希望便宜」优先达标低价，「均衡」只在能力差距小且节省明显时选低价，「接受昂贵」优先能力，同分时选已知价格较高的模型。缺价本身不会触发能力补查。

## 单模型路由与多模型协作

| Pi 命令 | 用途 |
| --- | --- |
| `/classify 任务` | 查看分数、来源和推荐，只做分类 |
| `/bakarouter` | 为普通输入选择一个模型回答，显示实际回答模型 |
| `/superbakarouter` | 先选统筹模型，再按各工作包的任务和价格偏好选执行模型 |
| `/bakamodels`、`/bakamodels refresh` | 查看各榜版本和同步状态，或立即刷新自动来源 |
| `/bakamodels import superclue ./快照.json` | 导入官方快照，来源也可填 `livebench` 或 `decathlon` |
| `/bakamodels prices` | 单独刷新官方 API 参考价格 |

协作模式由统筹按任务规模拆分工作、接收汇报、使用工具并整合成果。每批工作包数量由任务决定，同时最多执行两个。单个工作包遇到临时服务错误时可改派合格的备选模型。各角色遵守同一文件保护策略，执行调用分别计费。[协作模式说明](../docs/team-routing.md)

## 升级与回退

本版将任务识别提示词、分数换算和价格策略分别记录为 `benchmark-needs-v1`、`task-percentiles-v1` 和 `benchmark-price-v1`。Python 锁文件新增 PyArrow 26.0.1，用于读取 Arena 的 Parquet 文件。独立 CLI 和 HTTP 分类接口沿用原有的 0–4 分契约。

已有安装切换到 `v0.6.0` 后，在仓库根目录运行 `uv sync --frozen --python 3.12`，再在 Pi 中执行 `/reload`。需要恢复上一版时，先退出 Pi 并保存本地改动，然后切换到固定标签 `v0.5.0`，按该版本锁文件恢复依赖。[版本管理与回退](../docs/versioning.md)
